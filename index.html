The Odyssey, three ways

What. An interactive visualisation of The Odyssey across three tellings: Homer's poem, EPIC: The Musical and Christopher Nolan's 2026 film. Hover any character, place, song or actor and it tells you the story behind it. Switch on previews and the songs play.

How. I built the dataset by hand: 130 characters, places, songs and actors, and 235 relationships between them. I loaded it into a Neo4j database, then drew it with d3.js as a hive plot, a layout that gives each type of thing its own axis so the connections between them stay readable instead of collapsing into a hairball.

Why. The film was coming out, the musical was everywhere, and I wanted to know whether the three versions actually tell the same story. They don't quite. Building it also exposed a missing connection that weeks of reading the data in a spreadsheet had hidden, which became a piece for Nightingale.

The BeyHive Plot

What. Beyoncé's solo discography as one interactive picture: eight albums wearing their own cover art, over 100 songs coloured by era, all seven tours, and every credited collaborator with a live Wikipedia bio. Toggle previews, hover a song, and it plays.

How. No database this time. The structure (albums, tours, era facts) is hand-curated in the file, and everything else arrives live when the page loads: tracklists, artwork and 30-second previews from the iTunes Search API, collaborator photos and bios from Wikipedia's API.

Why. Once I'd worked out the layout on The Odyssey, I wanted to try it on a dataset people would actually argue about.

Notes and highlights for GraphAcademy

What. A note-taking feature on Neo4j's free learning platform. Select any text or image in a lesson, highlight it, add a note, and everything you save collects on a "Your notes" page at the end of the course.

How. I built it in React and TypeScript inside the platform's codebase. The hard parts were anchoring a highlight to text that can change between site rebuilds, and making a save feel instant even when the network isn't.

Why. I wanted learners to be able to keep what they'd found useful without leaving the lesson to do it.

Empathometer

What. A documentation review tool that reads a page the way different readers would: a junior developer, a business user, a senior developer, an AI agent. Paste in a page, pick a persona, and it tells you where that reader would get stuck and what to change.

How. Python and FastAPI on the back end, plain HTML, CSS and JavaScript on the front, with the OpenAI API doing the reading. Each persona is a prompt with a point of view, not a checklist.

Why. "Is this clear?" is the question every docs team asks, and nobody can answer it for a reader they aren't.
